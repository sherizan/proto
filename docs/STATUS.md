## How to maintain this file

**At the start of a Claude Code session in this repo:** read this file first to see what's current.

**At the end of a Claude Code session:**
1. If anything in "Currently live" changed (versions, install paths, new releases), update the table.
2. Move freshly-completed work from "In progress" → "Done recently" with date + commit refs.
3. **If a change is something a designer would feel, add a designer-facing line to `CHANGELOG.md`** (under "Unreleased" until it ships). That file — not this one — feeds the website's release notes.
4. If new bugs surfaced, add to "Known issues / quirks".
5. If new follow-ups came up that aren't being acted on, open an issue on `sherizan/prototo-shared` (see CONTRACTS.md Backlog).
6. If a cross-cutting risk surfaced, add it to `RISKS.md`.
7. Update the "Last updated" line in the header.
8. Commit this file alongside whatever else the session produced — the file IS the handoff note.

Keep only the newest 5 "Done recently" entries: move older ones, word for word, to the top of the
"Done recently (older)" section of `docs/STATUS-ARCHIVE.md`. Cap: 30 KB (`~/Public/prototo-shared/check-contracts.sh` checks it).
